# Plan: keys service (stretch, for a dictation trial)

- Status: Done 2026-11-23
- Depends on: [python-scaffold](2026-11-23-python-scaffold.md)
- Design: [ADR-0007](../adr/0007-keys-service.md),
  [ADR-0006](../adr/0006-installation.md) (`odsodctl install --system`),
  PRD [keyboard](../prd/keyboard.md), PRD [dictation](../prd/dictation.md)
  (the keys-side ACs)

## Goal

- `components/keys/` holds the C keys service: today's remaps, frozen by
  sequences, then the Left Alt machine, pointers, the socket and the
  escape chord.
- `odsodctl install --system` builds and installs it, tested with fakes,
  so the owner can switch keyboards tomorrow in one step.

## Scope

- In: everything in ADR-0007 "Module layout" and "Tests", in the ADR-0007
  "Build order". `install --system` (`components/install/system.py`) and
  the system unit template. The `gcc` compile and the sequence replays in
  `mise run build` (this plan and python-scaffold are the only writers of
  `mise.toml`).
- Out: running `install --system`, stopping `odsod-keys.service`, or any
  access to `/dev/input` or `/dev/uinput` tonight. The owner gate (escape
  chord on the real host) is the owner's. Recorded fast typing (AC-6):
  written rollover sequences cover it until the owner records.

## Steps

1. Read the port source: `~/Code/github.com/odsod/machine/keys/odsod-keys.c`.
   Read only. Do not build or run it.
2. `state.c` with today's remaps only, no clock reads and no I/O; time is
   an input. `replay.c` runs a `.seq` file through it.
3. Freeze today's behavior: one `.seq` per remap rule from ADR-0007
   "Remaps (unchanged)", with the output the old program gives for the
   same input (read from its source). All pass before step 4.
4. Add the Left Alt machine, pointer devices, the escape chord, then the
   socket in `io.c`, each with its own sequences (ADR-0007 "Tests" table).
5. `keys.contract` message models and `test_contract.py`.
6. `install --system`: build into a temp dir, write the system unit and
   the notify-system unit, restart only on change. Tests with a fake
   `gcc` output dir, fake `systemctl` and a temp root prefix. Add `keys`
   to `install.contract.SERVICES` only when every sequence passes.
7. Write in Progress log the owner steps for the switch, from ADR-0006
   "Migration" step 3 and the ADR-0007 owner gate.

## Decisions to confirm

- The `.seq` grammar gains `repeat` in `out key`. ADR-0007 lists only
  `down|up`, but the old program forwards repeats and the freeze needs
  them.
- `install --system` sets the owner with
  `ExecStartPre=... chown <uid>:<gid> /run/odsod-daemon-keys`, and `io.c`
  gives the socket the uid and gid of that directory. ADR-0007 says
  install sets the owner, not how.
- The notify unit takes `User=` from `SUDO_USER`, else the passwd entry of
  `SUDO_UID`; the gid comes from `SUDO_GID`, else the primary gid.
- A pending Left Alt resolves on a key press only, not on a release or a
  repeat. The prose says "another key pressed".
- A second `paste` while one waits is ignored. One paste at a time.
- A new socket peer during dictation ends that dictation. Neither side
  keeps state across a reconnect.
- The escape chord releases held output keys in key-code order. `SIGTERM`
  uses the same routine; the grammar has no stop input.
- The service exits 1 when it finds no keyboard, as the old program does.
  It keeps running with no socket when the bind fails, so remaps still work.
- `--record` opens devices without a grab, so the owner stops the keys
  service first. The help text says so.
- `keys` joins `SERVICES` when the owner switches keyboards (ADR-0006
  migration step 3). Health expects every shipped unit, and the keys unit
  installs only for the dictation trial. `install --system` renders it
  without the list.
- This plan adds `system.py` only. The `install --system` command wiring
  belongs to the install-and-control plan, so the tests call the function.
- `mise run build` compiles the C code in `keys:compile` and replays every
  `.seq` through the component tests. No binary lands in the repo.
- `mise run build` now needs `gcc` and the Linux input headers on the host
  and on CI. ADR-0006 already lists them for `daemon:setup`.
