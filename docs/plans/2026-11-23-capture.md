# Plan: capture and retention

- Status: Draft

  PRD [ambient-recording](../prd/ambient-recording.md)

## Goal

- The `capture` component writes both channels to the audio buffer, with
  its events and health, and the `capture` service runs it.
- `odsodctl retention` deletes old hour files.

## Scope

- In: everything in ADR-0011 "Module layout" and "Tests", the `capture`
  service file, the `retention` command.
- Out: the owner checks in ADR-0011 "Build without hardware".
  `capture_latency_ms` stays 0 until the owner's spike. Echo
  cancellation (deferred).

## Steps

1. Pure core with table tests on the virtual-time loop: the anchor, the
   writer offsets and hour split, the stall and suspend rules, the mic
   checks (ADR-0011 "Block loop and time anchoring", "Writer", "Stall,
   suspend and restart", "Mic checks").
2. Fake `pw-record` and fake `pactl` scripts in the component's tests.
3. I/O shell: one `pw-record` per channel, `pactl subscribe`, health
   faults, `start`, `stop` and `gap` records, `sd_notify`.
4. Enable the `capture` line in `services/capture.py`; add `capture` to
   `install.contract.SERVICES`.
5. `retention` and its command; enable its line in the root `cli.py`.
6. System tests from ADR-0011 "Tests" in the root `tests/`.
7. Real-host smoke (this host has a mic and PipeWire):
   `ODSOD_DAEMON_ROOT=$(mktemp -d)`, run `odsodctl run capture` for 60 s,
   then SIGTERM. Use `uv run odsodctl`. Check both channel files grow at 32,000 bytes per
   second, the `start` and `stop` records, and the health file. Check
   with `pactl list source-outputs` that the sys channel reads a monitor.
   Write `pactl get-default-sink` and the monitor name in Progress log.
   If the sink is `auto_null`, write `sys smoke: not proven (null sink)`.
   Delete the temp root.

## Decisions to confirm

- Drift is `arrival - capture_latency_ms - (end of this block)`, where the
  end includes the block. ADR-0011 writes `arrival - (t0 + n/16000)` with
  `n` since the first sample. With a nonzero `capture_latency_ms` the prose
  gives a constant positive drift and re-anchors on every block, so the code
  subtracts the latency. With the default 0 the two forms agree.
- The drift history resets after a seek or a drop, so the next ten blocks do
  not carry the old step. ADR-0011 does not say.
- A dropped block writes no record. Only a seek-forward hole of 1 s or more
  gives a `gap` with reason `clock`, as the plan's test says.
- The writer trims the front of a block that overlaps the existing file size
  and skips a block that ends before it, so a restart or a clock step back
  never writes backward (ADR-0003).
- A `pw-record` that exits on its own is retried after `stall_restart_s`; a
  stall restart happens right after the timeout.
- A `stop` record goes only on a clean shutdown, and only for a channel that
  wrote audio in this run. An exception writes no `stop` (ADR-0011).
- `services/runner.py` sends `WATCHDOG=1` every half interval, which would
  defeat capture's gate. A component now sets `WATCHDOG_OWNER` and the
  runner leaves the ping to it. Capture sets it.
- An unknown mute state (no `pactl`, no server) counts as not muted, so a
  broken `pactl` never hides `mic-silent`. `mic-muted` needs a real muted
  answer.
- `mic-muted`'s `since` is the first observation of the mute flag;
  `mic-silent`'s is the first zero block.
- The fake `pw-record` and `pactl` are Python scripts in
  `components/capture/tests/bin/`. The component tests use an in-process
  fake process on the virtual clock; the root system tests put the scripts
  first on `PATH`.
- Config seconds are floats, not ints, so the system tests can set values of
  0.3 s. The ADR-0011 JSON shows integers.
- Retention deletes when `now - hour_start >= retention_days`, so a file
  goes exactly when its first second turns 14 days old.
- `install.contract.SERVICES` names `capture` before its unit template
  exists; the install plan adds the template.
