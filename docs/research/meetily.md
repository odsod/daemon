## Scope

Meetily is a local-first meeting recorder, live transcriber, and meeting summarizer for Windows, macOS, and Linux ([README.md](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/README.md#L69-L106)). It has no dictation mode or OS cursor typing; a feature request for live dictation was closed ([issue #719](https://github.com/Zackriya-Solutions/meetily/issues/719)).

## Architecture (processes, services, IPC, state)

- **Main desktop process**: Single Tauri 2 binary (`meetily`) hosting a Next.js static export (`frontend/out`) in a WebView, guarded by `tauri-plugin-single-instance` ([frontend/src-tauri/tauri.conf.json](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/tauri.conf.json#L6-L11), [frontend/src-tauri/Cargo.toml](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/Cargo.toml#L160-L161)).
- **Sidecar processes**:
  - `llama-helper`: External Rust binary using `llama-cpp-2`, spawned by `SidecarManager` over JSON-lines stdin/stdout (`Generate`, `Ping`, `Shutdown`), kept alive with a 300s default idle timeout (`LLAMA_IDLE_TIMEOUT`) ([frontend/src-tauri/src/summary/summary_engine/sidecar.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/summary/summary_engine/sidecar.rs#L24-L105), [llama-helper/src/main.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/llama-helper/src/main.rs#L22-L51), [frontend/src-tauri/src/summary/summary_engine/models.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/summary/summary_engine/models.rs#L325)).
  - `ffmpeg`: Bundled external binary (`binaries/ffmpeg`) used via `ffmpeg-sidecar` for audio checkpoint encoding/concatenation and format conversion ([frontend/src-tauri/tauri.conf.json](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/tauri.conf.json#L111-L114), [frontend/src-tauri/Cargo.toml](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/Cargo.toml#L146)).
- **IPC**: Frontend calls Rust via Tauri `invoke_handler` commands ([frontend/src-tauri/src/lib.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/lib.rs#L732-L954)). Rust pushes live updates via Tauri events: `transcript-update`, `speech-detected`, `transcription-progress`, `transcription-warning`, `transcription-error`, `recording-stop-complete` ([frontend/src-tauri/src/audio/transcription/worker.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/transcription/worker.rs#L192-L336), [frontend/src-tauri/src/tray.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/tray.rs#L95)).
- **In-process audio pipeline**: `RecordingManager` coordinates `RecordingState` (atomics + unbounded `tokio::sync::mpsc` channels), `AudioStreamManager`, `AudioPipelineManager` (mixing + VAD), `RecordingSaver`, and `AudioDeviceMonitor` ([frontend/src-tauri/src/audio/recording_manager.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/recording_manager.rs#L186-L242)).
- **Background threads**: On Linux, `pulse_enumerator` runs one dedicated `pulse-enum` OS thread owning a persistent `libpulse` `Mainloop` + `Context` to avoid connect/disconnect churn ([frontend/src-tauri/src/audio/capture/pulse_enumerator.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/capture/pulse_enumerator.rs#L134-L233)).

## Audio capture (API, rate, buffering, system audio)

- **Linux capture API (PulseAudio / PipeWire)**:
  - Uses `libpulse-binding` 2.30.1 directly (`PulseCapture`) for both system audio (sink `.monitor` sources, stereo) and microphones (real input sources, mono) ([frontend/src-tauri/src/audio/capture/pulse_linux.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/capture/pulse_linux.rs#L1-L54), [frontend/src-tauri/src/audio/capture/pulse_linux.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/capture/pulse_linux.rs#L147-L190)).
  - Requests fixed `Format::FLOAT32NE` at 48,000 Hz so PulseAudio/PipeWire resamples server-side, with `fragsize = 48000 / 50 * channels * 4` (20ms fragments) and `FlagSet::DONT_MOVE` ([frontend/src-tauri/src/audio/capture/pulse_linux.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/capture/pulse_linux.rs#L53), [frontend/src-tauri/src/audio/capture/pulse_linux.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/capture/pulse_linux.rs#L182-L190)).
  - On graceful stop (`should_finish`), calls `stream.update_timing_info()` to obtain the server `write_index` cutoff and drains queued packets up to that frame boundary within a 250ms deadline ([frontend/src-tauri/src/audio/capture/pulse_linux.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/capture/pulse_linux.rs#L217-L261)).
  - Falls back to `cpal` ALSA only when the PulseAudio/PipeWire server is unreachable, filtered to a whitelist (`default`, `pipewire`, `pulse`) and serialized behind a process-global `ALSA_GLOBAL_LOCK` mutex to prevent `alsa-lib` heap corruption ([frontend/src-tauri/src/audio/devices/platform/linux.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/devices/platform/linux.rs#L14-L39), [frontend/src-tauri/src/audio/stream.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/stream.rs#L117-L150)).
- **macOS / Windows capture**: macOS uses `cidre` Core Audio global mono tap (`CoreAudioCapture`) or ScreenCaptureKit via `cpal`; Windows uses `cpal` ([frontend/src-tauri/src/audio/stream.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/stream.rs#L93-L165)).
- **Resampling and mic DSP**:
  - Pipeline runs at 48,000 Hz mono (`audio_to_mono`). Non-48 kHz devices use a persistent `rubato::SincFixedIn<f32>` resampler with 512-sample input buffering and BlackmanHarris2 windowing ([frontend/src-tauri/src/audio/pipeline.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/pipeline.rs#L454-L591), [frontend/src-tauri/src/audio/pipeline.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/pipeline.rs#L630-L711)).
  - Microphone-only chain: 80 Hz `HighPassFilter` -> optional RNNoise (`nnnoiseless`, disabled by default via `RNNOISE_APPLY_ENABLED = false`) -> stateful EBU R128 `LoudnessNormalizer` targeting -23 LUFS with a -1.0 dBTP 10ms lookahead `TruePeakLimiter` ([frontend/src-tauri/src/audio/pipeline.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/pipeline.rs#L497-L540), [frontend/src-tauri/src/audio/pipeline.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/pipeline.rs#L752-L810), [frontend/src-tauri/src/audio/ffmpeg_mixer.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/ffmpeg_mixer.rs#L20), [frontend/src-tauri/src/audio/audio_processing.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/audio_processing.rs#L100-L225)). System audio is captured raw with no DSP ([frontend/src-tauri/src/audio/pipeline.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/pipeline.rs#L536-L540)).

## VAD and segmentation

- **Engine**: `silero_rs` (`emotechlab/silero-rs` rev `26a6460`) wrapped by `ContinuousVadProcessor` running at 16 kHz in 30ms frames (480 samples) ([frontend/src-tauri/Cargo.toml](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/Cargo.toml#L103), [frontend/src-tauri/src/audio/vad.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/vad.rs#L9-L73)).
- **Resampling to 16 kHz**: `ContinuousVadProcessor::resample_to_16k` downsamples from 48 kHz using a moving-average low-pass filter plus linear interpolation ([frontend/src-tauri/src/audio/vad.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/vad.rs#L119-L162)).

- **Live vs batch redemption policy**:
  - Live recording uses `VAD_REDEMPTION_TIME_MS = 500` ms; the comments explain that 400ms fragmented a 26-minute meeting into 322 clips (median 3.5s) causing Whisper hallucinations, while 2000ms held segments open indefinitely during continuous system audio ([frontend/src-tauri/src/audio/pipeline.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/pipeline.rs#L14-L25), [frontend/src-tauri/src/audio/pipeline.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/pipeline.rs#L1019-L1044)).
  - Batch import (`import.rs`) and retranscription (`retranscription.rs`) use `VAD_REDEMPTION_TIME_MS = 2000` ms ([frontend/src-tauri/src/audio/import.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/import.rs#L54-L59), [frontend/src-tauri/src/audio/retranscription.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/retranscription.rs#L48-L53)).
- **Segment dispatch & flush**: Segments under 800 samples (50ms at 16 kHz) are dropped as short ([frontend/src-tauri/src/audio/pipeline.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/pipeline.rs#L1145-L1161)). On stop, `AudioPipelineManager::force_flush_and_stop` sends sentinel chunks (`chunk_id >= u64::MAX - 10`), drains the Linux ring buffer, pads any remaining partial 30ms VAD frame, and force-ends active speech using `session.get_current_speech()` trimmed to the exact unpadded sample count ([frontend/src-tauri/src/audio/pipeline.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/pipeline.rs#L1180-L1209), [frontend/src-tauri/src/audio/pipeline.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/pipeline.rs#L1317-L1360), [frontend/src-tauri/src/audio/vad.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/vad.rs#L165-L235)).
- **No max-duration cap**: `ContinuousVadProcessor` warns once when `current_speech.len() > 1_000_000` samples (~62.5s at 16 kHz) but does not force-split uninterrupted speech ([frontend/src-tauri/src/audio/vad.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/vad.rs#L238-L242)).

## Post-processing (LLM cleanup, prompts, glossary, replacements)

- **Transcript cleanup**: Whisper output passes through a heuristic `WhisperEngine::clean_repetitive_text` call ([frontend/src-tauri/src/whisper_engine/whisper_engine.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/whisper_engine/whisper_engine.rs#L651)). ## Known pitfalls (top Linux/Wayland issues from the tracker)

- **PipeWire quantum shrink glitches calls**: Recording glitches concurrent Teams/Zoom/WebRTC audio on Linux due to PipeWire quantum shrink ([issue #433](https://github.com/Zackriya-Solutions/meetily/issues/433)).
- **Raw ALSA probing causes audible pops and messy device pickers**: Polling `cpal`/ALSA caused static pops on audio output ([issue #838](https://github.com/Zackriya-Solutions/meetily/issues/838)) and exposed raw `sysdefault:`/`hw:` PCM names ([issue #437](https://github.com/Zackriya-Solutions/meetily/issues/437)); Meetily moved to `libpulse-binding` + `pulse-enum` to avoid this, though monitor-source edge cases remain open ([issue #896](https://github.com/Zackriya-Solutions/meetily/issues/896), [issue #701](https://github.com/Zackriya-Solutions/meetily/issues/701)).
- **VAD pause splicing and tail draining**: Pausing mid-sentence leaves the Silero VAD segment open and splices it with post-resume audio ([issue #835](https://github.com/Zackriya-Solutions/meetily/issues/835)); capture/mixer tail drain and final VAD send errors are tracked in [issue #773](https://github.com/Zackriya-Solutions/meetily/issues/773) and [issue #775](https://github.com/Zackriya-Solutions/meetily/issues/775).
- **Linux WebKitGTK / Wayland / tray bugs**: Blank white window on KDE/Wayland with WebKitGTK DMABUF ([issue #435](https://github.com/Zackriya-Solutions/meetily/issues/435)), WebKitWebProcess abort in AppImage ([issue #933](https://github.com/Zackriya-Solutions/meetily/issues/933)), AppImage Wayland workaround ([issue #895](https://github.com/Zackriya-Solutions/meetily/issues/895)), and tray "Quit" not exiting on Linux ([issue #910](https://github.com/Zackriya-Solutions/meetily/issues/910)).
- **Vulkan VRAM detection missing in `llama-helper`**: `detect_vram_gb()` has no Vulkan path and falls back to 4 GB, offloading only ~10/33 layers on Linux Vulkan ([llama-helper/src/main.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/llama-helper/src/main.rs#L131-L154), [issue #552](https://github.com/Zackriya-Solutions/meetily/issues/552)).
- **Ignored workspace `[patch.crates-io]`**: `[patch.crates-io]` in `frontend/src-tauri/Cargo.toml` is ignored by Cargo workspaces, so builds silently used crates.io `cpal` 0.15.3 ([frontend/src-tauri/Cargo.toml](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/Cargo.toml#L214-L216), [issue #911](https://github.com/Zackriya-Solutions/meetily/issues/911)).

## Ideas for the daemon

- **Copy: Talk to PipeWire/PulseAudio directly, not ALSA via `cpal`**. Using `libpulse` (or native PipeWire) lets the server resample/remix monitor sources to a fixed 48 kHz float32 format, avoids raw ALSA probing pops ([issue #838](https://github.com/Zackriya-Solutions/meetily/issues/838)) and `alsa-lib` thread-safety crashes ([frontend/src-tauri/src/audio/devices/platform/linux.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/devices/platform/linux.rs#L14-L28)), and keeps one persistent enumerator thread ([frontend/src-tauri/src/audio/capture/pulse_enumerator.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/capture/pulse_enumerator.rs#L1-L16)).
- **Copy: Position-tracked dual-stream ring buffer with lead tolerance**. Meetily's Linux `PositionedAudio` mixer waits up to 1s (`LINUX_MAX_STREAM_LEAD_SAMPLES`) before zero-padding a lagging PipeWire stream, preventing 150-330ms mic/monitor delivery skew from corrupting mixed audio ([frontend/src-tauri/src/audio/pipeline.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/pipeline.rs#L174-L302)).
- **Copy: Server-timing closeout on stop**. Querying `stream.update_timing_info()` for `write_index` and draining to that exact frame boundary prevents cutting off the last words when stopping a recording or releasing a push-to-talk key ([frontend/src-tauri/src/audio/capture/pulse_linux.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/capture/pulse_linux.rs#L217-L261)).
- **Copy: Explicit Silero VAD tuning and separate live vs batch redemption**. `positive=0.50`, `negative=0.35`, `pre_pad=300ms`, `post_pad=400ms`, `min_speech=250ms`, with 500ms redemption for live vs 2000ms for batch ([frontend/src-tauri/src/audio/vad.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/vad.rs#L46-L61), [frontend/src-tauri/src/audio/pipeline.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/pipeline.rs#L14-L25)). Also add a hard max segment duration (which Meetily lacks) so continuous speech never grows unbounded.
- **Copy: Strip reasoning tags and pre-fill empty `<think>` for local Qwen models**. `clean_llm_markdown_detailed` and `QWEN35_NONTHINKING_TEMPLATE` prevent local reasoning models from leaking chain-of-thought into cleanup or summary output ([frontend/src-tauri/src/summary/processor.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/summary/processor.rs#L10-L49), [frontend/src-tauri/src/summary/summary_engine/models.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/summary/summary_engine/models.rs#L266-L276)).
- **Copy: 30-second incremental audio checkpoints for crash recovery**. Writing small MP4 chunks on disk every 30s keeps RAM flat during always-on or multi-hour recordings ([frontend/src-tauri/src/audio/incremental_saver.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/incremental_saver.rs#L17-L100)).
- **Avoid: Mixing mic and system audio before ASR if you want speaker attribution**. Meetily mixes both into one mono track before VAD/Whisper, losing free "You" vs "Other" attribution ([frontend/src-tauri/src/audio/pipeline.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/pipeline.rs#L1130-L1165), [issue #642](https://github.com/Zackriya-Solutions/meetily/issues/642)).
- **Avoid: Leaving VAD open across pause/resume and omitting `initial_prompt`**. Flush VAD on pause to avoid splicing unrelated speech ([issue #835](https://github.com/Zackriya-Solutions/meetily/issues/835)), and wire a glossary into Whisper `initial_prompt` (which Meetily omits).
- **Avoid: Requesting small PulseAudio `fragsize` without testing PipeWire quantum impact**. Requesting 20ms fragments can shrink PipeWire's graph quantum and glitch active WebRTC calls ([frontend/src-tauri/src/audio/capture/pulse_linux.rs](https://github.com/Zackriya-Solutions/meetily/blob/2166bc6fe3ba585580f3f94b79cda7e7b91deb76/frontend/src-tauri/src/audio/capture/pulse_linux.rs#L185-L188), [issue #433](https://github.com/Zackriya-Solutions/meetily/issues/433)).
